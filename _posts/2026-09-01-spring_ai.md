# Spring AI

## 개요

### 왜 Spring 기반 AI를 알아야 할까?

단도직입적으로 말하자면, 기존 Spring 애플리케이션을 버리지 않고 AI 기능을 붙이기 위해서다. 기존의 Java/Spring 코드, DevOps체계, 보안이나 트랜잭션 같은 엔터프라이즈 기능을 그대로 활용할 수 있고 기존 서비스/레포지토리나 사내 DB, API를 AI와 연결하기 쉽다는 장점이 있다.

Spring 없이 LLM을 직접 붙이게 되면, LLM 벤더마다, 즉 OpenAI, Claude, Gemini 얘네 마다 호출 방식이 다르기에 코드를 하나하나 다 만들어주어야 한다. 이걸 프로젝트 마다 또 프롬프트 처리, RAG, 메모리, Tool calling 등 처리를 반복해야 한다. 

즉, Spring의 추상화, DI, Auto Configuration을 AI 영역에도 적용할 수 있게 된다.

#### 추상화

Spring Data가 JPA, MongoDB, Redis를 Repository라는 공통 인터페이스로 감싸듯이, 
Spring AI는 OpenAI, Claude, Gemini, Ollama 같은 모델들을 **ChatModel**이라는 공통 인터페이스로 추상화한다.
따라서 애플리케이션 입장에서는 어떤 LLM 벤더인지 덜 의존하는 코드를 만들 수 있다

### 그래서 Spring AI는

- **LLM**
- **Embedding Model**
- **Vector DB**
- **RAG**
- **Tool Calling**
- **MCP**

같은 기능들을 일관된 Spring 방식으로 사용할 수 있게 해주는 프레임워크다. 
나의 애플리케이션과 LLM 모델 사이를 중재하는 계층으로 보면 좋다.

### 주요 구성 요소

| 개념                  | 역할                            |
| ------------------- | ----------------------------- |
| `ChatModel`         | 여러 LLM을 공통 방식으로 추상화           |
| `ChatClient`        | LLM을 편하게 호출하는 Fluent API      |
| `Prompt / Message`  | LLM에 전달할 입력 구성                |
| `Structured Output` | LLM 응답을 Java 객체로 변환           |
| `Advisor`           | 요청 과정에 Memory, RAG 등의 기능 끼워넣기 |
| `EmbeddingModel`    | 텍스트 등을 벡터로 변환                 |
| `VectorStore`       | 임베딩 벡터 저장 및 검색                |
| `RAG`               | 외부 문서를 검색해서 LLM에게 제공          |
| `Tool Calling`      | LLM이 Java 메서드 등을 실행           |
| `MCP`               | 외부 Tool/Resource와 표준 방식으로 연결  |
| Observability       | AI 호출 tracing/metric 관리       |

- Fluent API : 메서드를 자연스럽게 이어서 호출할 수 있게 만든 API 스타일
  
  각 메서드가 다음 메서드를 호출할 수 있는 객체를 반환

  ```java
  // 예시 - . 으로 이어진 method chaining과 의미 있는 method 이름으로 쉽게 읽히게 설계한 API
  chatClient
      .prompt()
      .user("안녕")
      .call()
      .content();
  ```

## ChatClient API

### Prompt 객체

LLM에 전달할 메세지와 모델 실행 옵션(model, temperature, maxToken 등)을 담아 ChatModel에 전달하는 요청 객체

- Message : LLM과 주고 받는 대화 정보를 역할별로 표현하는 객체
  
  role(user/system/assistant/tool 등)과 내용으로 구성

### ChatModel vs ChatClient

1. ChatModel

   - 여러 LLM의 요청/응답 방식을 공통 인터페이스로 추상화한 핵심 인터페이스

     `import org.springframework.ai.chat.model.ChatModel;`

   - Spring 표준 Prompt를 각 모델에 맞는 API 요청 형식으로 바꾸고, 모델의 JSON 응답을 `ChatResponse`로 변환해준다.

2. ChatClient

   - ChatModel 위에 있는 고수준 Fluent API
   - 프롬프트 구성, Advisor, Tool, 응답 처리 등을 편하게 chaining해서 사용

#### 코드 예제

```java
chatClient        
    .prompt()        // 대화 요청 시작
    .user("안녕!")    // 유저의 프롬프트(메세지)
    .call()          // LLM 호출
    .content();      // 응답 문자열만 추출해줘 
```

결국 애플리케이션 코드에서는 ChatClient를 쓰고, ChatClient가 내부적으로 그 ChatModel을 사용해 실제 모델 호출을 수행한다.

이후 ChatClient를 사용하려면 빌드할 필요가 있다. 
ChatClient.Builder는 ChatModel, System Prompt, Advisor, Tool 등의 기본 설정을 조합해 재사용 가능한 ChatClient를 만드는 구성 API다.
이 Builder에 설정한 내용은 ChatClient 전체에 공통으로 적용햘 기본 값들이다.
따라서 요청할 때마다 시스템 프롬프트나 Advisor를 다시 설정할 필요가 줄어든다.

```java
// 예시
ChatClient.builder(chatModel)
    .defaultSystem("너는 블로그 AI야.")
    .defaultAdvisors(...)
    .build();
```

#### 정리

```text
ChatModel
   ↓
Builder
   ├─ System Prompt 설정
   ├─ Advisor 설정
   ├─ Tool 설정
   ↓
build()
   ↓
ChatClient
```

### 동기와 비동기

1. 동기

    ```java
    public String generation(@RequestParam String userInput) {
        return chatClient.prompt()
            .user(userInput)
            .call()                 // 응답이 올 때까지 대기
            .content();
    }
    ```

2. 비동기

    ```java
    public Flux<String> stream(@RequestParam String userInput) {
        return chatClient.prompt()
            .user(userInput)
            .stream()             // 생성되는 대로 토큰/청크 단위 반환
            .content();           // GPT 쓸 때 글자가 실시간으로 나오는 느낌
    }
    ```

### ChatResponse

LLM이 반환한 전체 결과는 ChatResponse에 담긴다.
구조는 아래와 같다.

```text
ChatResponse
 ├─ List<Generation>
 │      └─ Generation
 │           ├─ AssistantMessage
 │           └─ Metadata
 │
 └─ ChatResponseMetadata
```

이 호출 결과는 원하는 수준에 따라 꺼낼 수 있다. `ChatResponse` 객체로 받으면 전체 결과를, `Generation`으로 받으면 응답 후보를, `String`객체로 받아 `.content()`로 뽑아내면 응답 텍스트만 받아낼 수 있다.

### application.yaml

어떤 ChatModel을 활성화할지 설정할 수 있다.
예제는 아래와 같다.

```yaml
ai:
  model:
    chat: openai

  openai:
    api-key: ${OPENAI_API_KEY}
    chat:
      options:
        model: gpt-4o-mini
        temperature: 0.7
```

이제 구현에 필요한 최소한의 이해는 마쳤다.
